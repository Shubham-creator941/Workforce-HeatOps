# ADR 0002: Deterministic Liljegren thermal engine

## Context

P0-02 requires auditable Estimated Outdoor WBGT from normalized meteorology. Rewriting the equations from memory, substituting Heat Index, or delegating to an opaque package would weaken scientific equivalence. The original Argonne WBGT 1.1 implementation is preserved in `mdljts/wbgt` with a C99/double-precision adaptation.

## Decision

Vendor the preserved C99/double-precision implementation at upstream commit `cd672a886880b67f3f27bdbf75038d8f7ff0bac2`, retain all notices, and expose it through a small CPython binding. The adaptation's 500-iteration cap is restored to Argonne WBGT 1.1's original value of 50 and marked inline. A typed `ThermalEngine` protocol isolates callers from this implementation. Python owns validation, UTC normalization, result states, warnings, and serialization; equations remain isolated in the attributed C source.

`pywbgt` is not a production dependency because its GPL-3.0 licensing and native Cython/OpenMP packaging are unnecessary here. No `pywbgt` source was copied.

## Input semantics

The contract freezes Celsius, percent RH, actual downward GHI in W/m², wind in m/s, explicit wind height in meters, pressure in hPa (numerically equivalent to the reference's millibars), coordinates in decimal degrees, timezone-aware timestamps normalized to UTC, and an explicit solar averaging period in whole minutes.

WBGT 1.1 centers solar position on the meteorological averaging interval. It accepts a wind measurement height and can estimate 2 m wind from other heights only after choosing atmospheric stability from vertical temperature difference and urban/rural surface class. Those inputs are not in the normalized P0-02 contract. Therefore this release supports wind measured at 2 m only and returns `UNSUPPORTED_INPUT` otherwise; it does not invent a wind profile.

## Reference methodology

Golden outputs were generated by compiling the upstream `src/wbgt.c` independently with Clang and invoking `calc_wbgt` from a standalone command-line runner. Fixtures record upstream commit, input, output, and generation method. Tests compare every component at an absolute tolerance of `1e-10 °C`, tight enough to detect mapping or implementation changes while allowing decimal serialization of the oracle output.

## Licensing implications

The root MIT license continues to cover Workforce HeatOps-owned code. Vendored files retain Max Lieblich's MIT notice and the separate Argonne license, conditions, acknowledgment, and disclaimer. `THIRD_PARTY_NOTICES.md` records origin and modification status.

## Consequences

The service build requires a C99 compiler and produces a platform-native CPython extension. Runtime calculation is offline, deterministic, and has no database, provider, or LLM access. Model non-convergence is an item result and never invokes a fallback.

## Remaining questions

Provider integration must either supply verified 2 m wind or extend the normalized environmental contract with authoritative vertical temperature difference and surface classification before non-2 m adjustment can be enabled.
